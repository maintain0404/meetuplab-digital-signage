# GitHub Pages 메인 배포 전환

## 배경

현재 Firebase Hosting으로 정적 파일을 배포하고, PR Preview는 `FirebaseExtended/action-hosting-deploy`로 구성되어 있다. 계정 관리 복잡도와 외부 서비스 의존성을 줄이기 위해 GitHub Pages로 전환을 검토했다.

## 결정 사항

**메인 배포만** Firebase Hosting에서 GitHub Pages로 전환한다.  
**PR Preview는 Firebase Hosting을 유지한다.**

## 메인 배포: JamesIves/github-pages-deploy-action

메인 배포 액션으로 `JamesIves/github-pages-deploy-action`을 채택한다.

**주요 동작 방식**

- 지정한 `folder`의 파일을 `gh-pages` 브랜치에 푸시해 GitHub Pages에 배포한다.
- `clean: true`(기본값)로 소스에 없는 파일을 배포 브랜치에서 자동 삭제한다.
- `force: true`(기본값)로 force-push 방식이나, `false`로 설정하면 rebase 방식으로 전환된다.
- `contents: write` 권한이 필요하다.

**이 프로젝트에서의 설정 방향**

현재 프로젝트는 빌드 스텝 없이 정적 HTML을 그대로 서빙하므로 설정이 단순하다.

```yaml
- uses: JamesIves/github-pages-deploy-action@v4
  with:
    folder: .
    clean-exclude: |
      pr-preview/
```

> `clean-exclude: pr-preview/`는 PR Preview가 GitHub Pages로 전환될 경우 필요한 설정이다. 현재 결정(Firebase PR Preview 유지)에서는 불필요하나, 향후 전환 시를 대비해 명시한다.

## PR Preview를 Firebase에 유지하는 이유

GitHub Pages 기반 PR Preview(`rossjrw/pr-preview-action`)는 `gh-pages` 브랜치 공유 구조로 인해 메인 배포 액션과 충돌 제약이 있다.

- `pr-preview-action`은 메인 배포 액션에 `force: false` + `clean-exclude: pr-preview/` 설정을 요구한다.
- 커밋 히스토리 정리를 위한 `force_orphan: true`(`peaceiris/actions-gh-pages`)는 PR preview 폴더를 메인 배포마다 소멸시키므로 함께 쓸 수 없다.
- Firebase PR Preview는 PR별 전용 도메인(`pr-123.PROJECT.web.app`)을 제공하며 7일 만료·자동 정리 등 운영이 안정적이다.

## 포기한 대안

| 대안 | 포기 이유 |
|------|-----------|
| PR Preview도 GitHub Pages로 전환 | `force_orphan`과 비호환, 메인 배포와 `gh-pages` 브랜치 충돌 관리 부담 |
| Firebase 전체 유지 | 계정 관리·외부 의존성 감소 목적에 부합하지 않음 |
